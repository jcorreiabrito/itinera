## 1. Executive summary

Itinera is a genuinely well-built local-first application. The data layer is the strongest part of the product: a clean repository pattern, real soft-delete with trash and restore, a full timezone/datetime module, sanitised markdown, an offline-first service worker that actually precaches the app, and 116 passing API tests. The route skeleton and per-section empty/loading/error states are consistent. Nothing here suggests a rewrite.

What the audit found is a product whose **craft is concentrated in the data layer and absent at the edges** — the places where a user meets it: print, mobile map, language, dark mode, and the truthfulness of its own sync indicator. Three findings dominate:

1. **The app lies about backup.** With the home server unreachable — the exact condition a self-hosted traveller is in — the UI shows a green "Synced · Last synced just now" while nothing has left the device (`web/src/lib/db/sync.ts:320-329`, reproduced under an instrumented `vitest`). No banner, no pending dot, no error. On iOS Safari a non-installed PWA is evicted after ~7 days of disuse and the app never prompts installation. This is the single most trust-destroying state possible in an offline-first product, and it can precede irreversible loss.

2. **Print — the only output that leaves the app, and Goal 4 of the brief — is broken three independent ways.** The global `header, nav, aside, button:not(.print-keep) { display:none }` rule in `web/src/app.css:348-363` deletes the trip title, every day heading, every flight route line and every checklist label from the page (verified by printing the real built stylesheet in headless Chrome and diffing the PDF text layer). Dark-mode printing floods the sheet with `#111613` (74,079 dark pixels vs 642 in light mode) or prints `#f0f4f1`-on-white text. And the server PDF sums expenses 1:1 with no currency conversion, so a trip with one foreign-currency expense produces a document that contradicts the screen — `€1,120.00` where the app's own maths yields `984.00`.

3. **Localisation was applied to the dictionaries but not the components.** `web/src/lib/i18n.svelte.ts:47` types `t(key: string)` and falls back to returning the key, so nothing fails when a key is missing. Five keys are missing and render as raw identifiers in the UI (`edit_flight`, `edit_reservation`, `cost`, `add`, `optional` — the flight edit sheet is literally titled "edit_flight"). Beyond that: 237 untranslated attributes, 86 hardcoded English toasts, and hardcoded Portuguese sitting in the same views as hardcoded English — `itinerary/+page.svelte:327` renders "Clear filters" six lines above a hardcoded Portuguese empty-state sentence at `:333`.

Around those, the audit confirmed a set of defects that are individually small and share one root cause: **the design system has no source of truth**. `tailwind.config.ts:38-41` hardcodes the four status colours as hex literals while `app.css:52-55` and `app.css:89-92` define the same names as CSS variables with dark overrides that **nothing consumes**. Measured: `text-danger` is 2.98:1 on the dark surface — failing WCAG AA — while the correct dark value (5.11:1) sits unused three lines away. The same file defines only `primary-{100,600,700}` while `primary-{50,200,300,400,500,800,900,950}` are used 20 times across 8 files and **generate no CSS at all** — Tailwind silently drops unknown classes, so `ItineraryDay.svelte:269`'s badge renders as unstyled text with no border and no background, and there is no build error, warning, or failing test.

## 2. Current-state diagnosis

### 2.1 Design system: a config file that disagrees with itself

Three separate truth-claims exist for the same tokens and none of them is authoritative.

- **Status colours.** `tailwind.config.ts:38-41` defines `success/warning/danger/info` as hex literals. `app.css:52-55` defines `--color-success` etc. and `app.css:89-92` redefines them for `html.dark`. The built CSS contains `.text-danger{color:rgb(180 69 47 / var(--tw-text-opacity,1))}` — the _light_ hex — with no dark counterpart. The variables have **zero consumers**. 39 usages are affected, including `Field.svelte:33` (every form validation message — 117 `<Field>` usages, all rendered inside dark sheets and dialogs), `SyncStatusPill.svelte:28,111` (sync errors), `ExpenseRow.svelte:116-119` (the Paid toggle at 11px), and `MenuItem.svelte:25` (destructive items). Only `Badge.svelte:26-29` patches dark mode, and it does so with raw palette colours (`dark:text-emerald-400`).
- **The primary ramp.** Only `100/600/700` are defined (`tailwind.config.ts:15-19`). Verified against the fresh build: `.border-primary-200`, `.text-primary-800`, `.text-primary-400`, `.dark\:bg-primary-900\/30`, `.dark\:text-primary-300` each occur **0 times** in the emitted CSS, while `.bg-primary-100` occurs 7 times — so the grep method is sound. Affected: `ItineraryDay.svelte:269`, `WholeTripOverview.svelte:125,137,139,307,358`, `DestinationsWidget.svelte:57,72`, `ChecklistGroup.svelte:142`, `+page.svelte:205`, `settings/+page.svelte:367`, `checklist/+page.svelte:323,349,353`, `ApplyTemplateDialog.svelte:81`, `Badge.svelte:25`, `SyncStatusPill.svelte:24`.
- **Duplication.** `--radius-*` (`app.css:57-60`) and `--font-serif/--font-sans` (`app.css:62-63`) are re-declared as literals at `tailwind.config.ts:50-56,47-48` with zero `var(--radius` consumers. The CSS variables are decorative.

**Root cause:** `tailwind.config.ts:5` says "implemented exactly from docs/13-ui-ux.md". That file does not exist and never has. Every developer since has guessed a palette step, and Tailwind has silently accepted each guess.

### 2.2 Print and PDF

The browser path and the server path are two unrelated products that happen to share a name.

**Browser print (`window.print()`).** Single call site: `TripDataMenu.svelte:220-223` — `onclick={() => { open = false; window.print(); }}`, labelled with a hardcoded Portuguese string "Imprimir / Salvar PDF (Offline)" inside an otherwise-i18n'd menu. It is reachable from every trip tab and prints **whatever tab you are on**. On Itinerary the default selection is today (`itinerary/+page.svelte:46-49`), so "print my trip" produces one day with no scope indicator.

The `@media print` block (`app.css:348-406`) is the most defective code in the repository:

- It hides bare `header`, which is load-bearing content: the trip title (`trip/[id]/+layout.svelte:151,163`), each day's date heading (`ItineraryDay.svelte:263-268`), each flight's route line (`FlightCard.svelte:64-67`).
- It hides `button:not(.print-keep)`, and the checklist item text is a button child (`ChecklistItemRow.svelte:111-121`) as are overview event titles (`WholeTripOverview.svelte:357,372,446`). The paid/unpaid toggle is a button too (`ExpenseRow.svelte:114`) — **printing the Costs view loses the paid state entirely**.
- `.print-keep` (`app.css:352`) and `.no-print` (`app.css:356`) match **nothing** in the codebase. Neither does `[aria-label="Add"]`/`[aria-label="New"]` (`:360-361`).
- It resets the wrong element: `app.css:372` targets `#main-content` (the app wrapper, `+layout.svelte:53`) while the content container is `id="page-content"` (`trip/[id]/+layout.svelte:207`), whose padding survives.
- It kills link targets (`app.css:402-405`), so no booking URL reaches paper.
- There is **no `@page` rule anywhere in `web/src`** — no A4, no margins, no page numbers, no running header.
- It never undoes `document.documentElement.style.overflow = 'hidden'`, which `Sheet.svelte:54` and `Dialog.svelte:46` set — print with a sheet open and the layout is clipped.
- Dark mode is unhandled: `app.css:365-370` resets colour on `body`/`html` only, which does not override ~522 explicit `text-ink` utilities.

**Server PDF (WeasyPrint).** `api/app/services/pdf.py` + `api/app/templates/trip_pdf.html`. This is the better artefact and is still wrong in four ways:

- **Money is fabricated.** `pdf.py:295-302` sums `amountEstimate`/`amountActual` 1:1 with no currency, `fxRate` or `costType` applied, then formats with the trip's home currency (`:304-322`). `:349-362` builds day totals the same way. The web app converts via the stored snapshot (`money.ts:45-55`), excludes missing-rate items and flags them (`:68-76`), and multiplies `per_person` by `travelerCount` (`:82-92`). Verified with a fixture: PDF says `€1,120.00 / €1,100.00` where the app says `984.00 / 965.60` plus a warning. Page 5 carries "Total do dia: € 500,00" directly above 40 items each labelled "R$ 12,50".
- **Always English.** `pdf.py:229` reads `lang or trip.locale or trip.lang` — the trip schema has no `locale` or `lang` field (`schemas.ts:203-221`); language lives in the settings doc (`schemas.ts:377`). `api.ts:128-131` calls the endpoint with no `lang` param. The template hardcodes `<html lang="en">` (`trip_pdf.html:2`). Categories print raw (`trip_pdf.html:463,560`) even though `api/app/i18n.py:50-56,100-106` defines `cat_food…cat_other` keys that **nothing in `api/app` references**.
- **Fonts are not embedded.** The template names `"Inter", "Helvetica Neue", Arial` (`:44`) and `"Fraunces", Georgia` (`:53`) with no `@font-face`, while `deploy/api.Dockerfile:22-33` installs only `fonts-dejavu`. Every PDF renders in whatever fontconfig substitutes; the brand is absent from its own document.
- **No tag structure.** `html_to_pdf` (`pdf.py:500-513`) calls `write_pdf()` with no `pdf_variant`, so no PDF/UA-1. WeasyPrint supports it (`VARIANTS` at `weasyprint/pdf/pdfua.py:14`) — it costs one keyword argument, once the content is correct. Also `base_url` is dead plumbing (populated nowhere; the call site at `:524` omits it) and `trip_pdf.html` contains no images at all.

### 2.3 Mobile

The phone is the primary device and the flagship map feature does not work on it.

- **The map cannot be dragged on any phone.** `TripMap.svelte:262-266` passes `dragging: !L.Browser.mobile`, and Leaflet defines `mobile = typeof orientation !== 'undefined' || userAgentContains('mobile')` — true for every phone UA. Panning is off everywhere. The only remaining zoom affordance is `L.control.zoom({position:'bottomright'})` (`:272`), whose buttons are **30×30 CSS px** on touch (`.leaflet-touch .leaflet-bar a{width:30px;height:30px}`). In fullscreen the wrapper is `fixed inset-4 z-50` (`:420-423`) while the trip shell's bottom nav is also `z-50` and later in DOM order (`trip/[id]/+layout.svelte:230`, rendered at `:228` after `{@render children()}` at `:222`) — so the nav paints over the pin chip strip (`TripMap.svelte:520`) and the zoom buttons, and taps land on tab-bar links instead.
- **Fixed heights ignore viewport height.** The map is a hard `h-80` (320px) — 82% of a 393px landscape viewport before the 64px sticky header, date strip, search box and filter chips. `WholeTripOverview.svelte:270` puts `min-h-[450px]` and `max-h-[calc(100vh-200px)]` on the same element; min-height wins, so in landscape the grid is still 450px tall inside a 393px viewport.
- **Dirty-form loss.** `Sheet.svelte:112-119` closes on `touchDiffY > 80`; the only guard (`:94-99`) checks `scrollTop`, and the full-width `<header>` (`:167-174`) carries the same touch handlers as the 40px drag handle. A downward flick on the title bar — exactly where the thumb rests — discards an entire 526–749-line form with no confirm and no draft. Forms re-init on every open (`ItineraryItemSheet.svelte:196-199`).
- **Continuous compositing.** Three `backdrop-filter` layers are visible simultaneously during normal itinerary use: the sticky trip header (`trip/[id]/+layout.svelte:152`), the bottom tab bar (`:230`) and the map pin strip (`TripMap.svelte:520`), plus blurred `mix-blend-mode: multiply` orbs (`app.css:262-269`) that are only mitigated below 640px (`app.css:271-276`). All are fixed or sticky — the expensive case.
- **Feedback is missing where it is tapped most.** `app.css:112` removes `-webkit-tap-highlight-color` globally while `active:` appears only ~31 times and never on `MenuItem.svelte:22`, `ExpenseRow.svelte:41`, `ChecklistGroup.svelte:139`, `DateStrip.svelte:100-105,122-127`, `+page.svelte:253-269`, `checklist/+page.svelte:246-254`, or `TimelineEntryRow.svelte:158-163`. `navigator.vibrate` is used nowhere.
- **Installed Android never rotates:** `static/manifest.webmanifest` pins `"orientation": "portrait"`, and `"background_color": "#BFE1F1"` matches neither theme colour (`#fbf7f1` / `#111613`).

### 2.4 Widescreen

At 1440–3440px, 63–67% of the viewport is blank (`trip/[id]/+layout.svelte:207` caps content at `max-w-5xl`), while every edit is modal.

- **All ten sheets request `side="right"`** (`ItineraryItemSheet:383`, `ExpenseSheet:283`, `FlightSheet:277`, `ReservationSheet:369`, `ChecklistItemSheet:171`, `TripFormSheet:180`, `NewTripSheet:503`, `BudgetSheet:99`, `DuplicateTripSheet:82`, `UpdateDiffSheet:44`) and `Sheet.svelte:123` caps the right variant at `sm:w-[28rem]`. `:51` calls `showModal()`, `:143` dims the backdrop, `:54` sets `overflow:hidden` — the list behind is inert. Forms of 526–749 lines render in 448px while ~2900px sits free. (One live bug in that component: the drawer title reads "Edit expense" when editing an itinerary item — `ItineraryItemSheet.svelte:384` uses `t('edit_expense')`.)
- **No keyboard layer.** Five keydown handlers exist in the whole app (`CostsPane:185`, `AirportInput:208`, `Popover:43`, `ExportCalendarButton:51`, `itinerary/+page.svelte:343`) and no `svelte:window` listener in either layout. `DateStrip.svelte:85-114` is a `role="group"` of `aria-pressed` buttons with no roving tabindex; `Popover.svelte:34-48` never moves focus into or back from its panel and its panel is `role="group"` (`:55`), not a menu.
- **Reordering is broken.** `ItineraryDay.svelte:143-150` — `siblingIds()`'s two branches are byte-identical (`if (item.startTime) return items.filter(i => i.startTime === item.startTime)…` then the same expression on fallthrough), so for any item with a unique start time `sib.length === 1` and both `canMoveUp`/`canMoveDown` are false. Move up/down are permanently disabled (`TimelineEntryRow.svelte:125-130`). Note `move()` at `:159-175` indexes into `dayItemIds()` — the full day order — proving the author intended free reordering; only the guard is wrong.
- **Dead components.** `Sidebar.svelte` and `BottomTabBar.svelte` are exported from `lib/components/ui/index.ts:2,16` and imported nowhere. Both navs are hand-rolled inline (`trip/[id]/+layout.svelte:105-147` and `:228-254`) and have already diverged from the dead versions — and destinations are declared in three places (`tabs` at `:77-83`, the sidebar list, the dead component's props).

### 2.5 Information architecture and state

- **Only `?tab=` is honoured.** `?date=` is read once (`itinerary/+page.svelte:43-50`) and then written to memory only (`:231`); the Day/Overview toggle (`:244-267`) and filters (`:131-132`) never touch the URL. Same for checklist (`checklist/+page.svelte:81-82`), costs (`CostsPane.svelte:184,195`), trip list (`+page.svelte:17-18`). No `pushState`/`replaceState` anywhere. Reload, back and share lose your place.
- **The two navs disagree on the same URL.** `bookings/+page.svelte:10-12` renders Reservations when `tab` is absent _or_ any unrecognised value; the sidebar marks Flights active when `tab !== 'reservations'` (`+layout.svelte:130`) — so with no param, Flights shows `aria-current="page"` while Reservations renders. The mobile bar builds `href` without `?tab` (`:238`), so tapping Bookings always lands on Reservations and can never return to Flights.
- **No `+error.svelte` anywhere.** Any unmatched path boots the SPA router (adapter-static `fallback: 'index.html'`) and mounts SvelteKit's built-in error component — two lines of unstyled English, no `<main id="page-content">` (so the skip link at `+layout.svelte:46-51` points at a non-existent id), no link home.
- **Failed reads render as emptiness or deletion.** `+page.svelte:33-41` catches, toasts, and leaves `sectionsData` null → `totalTrips` is 0 → the user is told "Plan your first trip". `trip/[id]/+layout.svelte:41-49` catches to `trip = null` → renders "It may have been deleted on another device" (`en.ts:13`) with no Retry. In a local-first app, telling a user their data is gone because IndexedDB hiccuped is the worst possible false signal.
- **Cross-links are pane-level, not record-level.** Tapping a flight on the timeline opens the whole flight list from the top (`TimelineEntryRow.svelte:261` renders the entire card as `<a href={links.flights}>`). There is no per-item URL, and the reverse direction does not exist at all — grep for `/itinerary` in `components/flights/*` and `components/reservations/*` returns nothing.

### 2.6 Sync, conflicts and data safety

- **The false "Synced".** `sync.ts:320-329` treats a PouchDB `paused` event with no `err` as proof of a completed sync. For retryable failures `err` is never populated — PouchDB's `sync()` wrapper re-emits a bare `paused` (`pouchdb-browser/lib/index.js:10223-10236`, `function pushPaused(){…self.emit('paused')}` — no argument), while the real error goes only to the per-direction emitter (`:9529-9531`). Instrumented reproduction against `http://127.0.0.1:9/db/itinera`: `paused undefined` twice, then state `synced`, `lastSyncedAt` set, `pendingChanges false` — with zero bytes replicated. Creating a trip afterwards left the status byte-identical.
- **`pending` is unreachable.** `sync.ts:27` declares it in `SyncState`; no code path assigns it. `SyncStatusPill.svelte:26,80,88-90` (amber tone, UploadCloud icon, pending dot) are dead markup. `pendingChanges` is only ever derived from `navigator.onLine`.
- **Conflicts destroy edits silently.** `conflicts.ts:138-150` + `sync.ts:189-222` do whole-document last-write-wins, snapshot losers into `_local/itinera-conflicts`, then delete every conflict branch. Reproduced: A sets `title='National Museum'`, B sets `notes='buy tickets online'` → after resolution `title` is back to `Museum`; A's edit is gone. Recovery is impossible in-app: `settings/conflicts/+page.svelte:90-99` returns humanised field _names_ only, `:184-196` renders "differs in Title" with no values and no restore button, and `ConflictLogModal.svelte:63-64` prints `JSON.stringify(item.winner)` raw. Because the log lives under `_local/`, **it never replicates** — reviewing from another device honestly reports "No unresolved or unreviewed sync conflicts" (`:51`), and `markConflictReviewed` (`sync.ts:267-276`) permanently deletes the retained content.
- **JSON export silently drops every attachment.** `api/app/services/exports.py` emits only `build_attachment_manifest(docs)` — docId/name/mime/size/digest, no bytes — and `web/src/lib/db/importer.ts` deletes them on the way in (`delete raw._attachments;` at `:171,246,370`). The UI presents this as a backup ("Trip JSON exported.", "saved_to_device"). Only `api/app/services/backups.py` writes real binaries. `trips.duplicate()` also hard-returns `false` for `'attachment'` in `shouldInclude()` with no UI notice.
- **No restore path.** `api/app/routers/backups.py` exposes only `POST /backups/run` and `GET /backups`. Disaster recovery means SSH and filesystem archaeology on the home server.

### 2.7 Other verified defects the dimension sweep did not cover

The completeness critic found a whole feature with zero findings, plus a family of "class that doesn't exist" bugs:

- **ICS/calendar is broken in both generators.** `api/app/routers/calendar.py` builds flight `DTEND` on the same calendar date as `DTSTART`, so an overnight arrival produces an event that ends before it starts (invalid ICS). It escapes only `\n`, never folds at 75 octets, and hardcodes "Hospedagem" in Portuguese. The client exporter `web/src/lib/utils/ics.ts` omits flights and reservations entirely, emits no `DTEND`/`DURATION` (zero-length events), never escapes `,` `;` `\`, and embeds the generation timestamp in every UID (`item-${id}-${now}@itinera`) so re-importing duplicates every event.
- **Trash is the one screen with irreversible actions and no retention concept.** `settings/trash/+page.svelte` — no auto-purge exists anywhere in `src/`. A deleted trip lists as N+1 independent rows (cascade soft-delete marks every child at `trips.ts:232`; `trash.list()` lists them all). Row-level Restore calls `restoreDoc` only, never the cascading `trips.restore` (`trips.ts:246`) — so restoring a child of a deleted trip produces a document that stays invisible until the trip itself is restored.
- **The CSP comment contradicts the CSP.** `web/svelte.config.js:28-48` claims `mode: 'hash'` satisfies `script-src 'self'` "WITHOUT `unsafe-inline`", while the same block lists `'unsafe-inline'` for both script-src and style-src. SvelteKit then generates **no hashes at all** (`script_needs_csp` in `@sveltejs/kit/src/runtime/server/page/csp.js:153-156`) and the emitted meta in `build/index.html` contains zero `sha256` entries. `connect-src` and `img-src` allow `http: https: ws: wss:` — any origin — for an app whose stated constraint is three named services.
- **Class-does-not-exist family:** `text-destructive`/`border-destructive`/`ring-destructive/30` in `TripDataMenu.svelte:273,295,299` (no `destructive` colour exists) so invalid JSON paste shows **no error styling at all**; `scrollbar-none` in `TripMap.svelte:520` (not a Tailwind utility; `plugins: [forms]` only) so the pin strip shows a permanent scrollbar; `h-18` and `text-darker` in `settings/trash/+page.svelte:178,167`; `shadow-xs` and `dark:bg-primary-950/60` in `checklist/+page.svelte:322-323`; and the per-row purge button at `trash/+page.svelte:209-216` with no `variant`, rendering as a solid primary-green button (compare the correct `variant="destructive"` at `:234-241`).
- **Three UI behaviours contradict the app's own model.** Checklist delete (`checklist/+page.svelte:188-196`) soft-deletes with a success toast and **no Undo**, unlike `ItineraryDay.svelte:210-226`; the confirm dialog at `:492-495` promises "permanently clear" for an operation that only sets `deletedAt` (`checklist.ts:217-224`); `settings/+page.svelte:277-285` removes templates with no confirmation and no undo. Undo toasts auto-dismiss after 8000ms with no hover/focus pause (`toast.ts:40`).
- **Failure toasts that say success.** `FlightsPane.svelte:113` — `toast.error(t('flight_removed'))` inside the `catch` — and `ReservationsPane.svelte:123` likewise. The keys are success strings (`en.ts:240,242`). Every other call site in the codebase uses a `could_not_*` key.
- **Checklist loads twice per navigation:** two effects both depend on `id` (`checklist/+page.svelte:129-140`).
- **Settings mixes three save behaviours on one page.** Language writes immediately (`:334-349`); currency, first-day-of-week and the Carto key persist only on the Save button (`:376`) — with no unsaved-changes guard. And `:393-397` renders `<WifiOff />` inside the `{#if online}` branch, next to "You're online – these run on your home server" (`en.ts:169`).
- **`theme-color` never updates.** `app.html:9-10` keys it only to the OS preference, so a user who picks dark in-app gets a light status bar in standalone PWA mode.

### 2.8 Toolchain and performance

- **The documented developer path does not run.** `pnpm --version` fails: _"This version of pnpm requires at least Node.js v22.13. The current version of Node.js is v20.20.2"_ → `ERR_UNKNOWN_BUILTIN_MODULE: No such built-in module: node:sqlite`. `web/package.json` has **no `packageManager` field**, so corepack resolves `latest`. `pnpm-workspace.yaml` exists. Every documented script and the Playwright `webServer.command` are unrunnable as written. (`vite build` via the local binary still works — that is how the metrics above were measured.)
- **No CI, and the gates that exist are already red.** Prettier crashes on all 96 `.svelte` files; ESLint reports 120 errors across 52 files; 3 unit tests fail.
- **PouchDB is 71% of first-load JS** — a 459,338-byte modulepreloaded chunk. The critic correctly notes that deferring it buys shell paint only, not time-to-content, because the home screen's first content _is_ the trip list (and `pouchdb-find` is a module-level import in `db/pouch.ts:14-15`).
- **The service worker precaches 3,257,654 bytes at install, of which 1,271,364 are fonts and only 169,020 are reachable** across en and pt-BR.
- **Zero dynamic imports in the entire codebase.** Leaflet ships in a 300,485-byte chunk.
- **SW update can brick an open tab.** `service-worker.ts:36` `skipWaiting()` inside install + `:45` deleting the old cache inside activate + `:47` `clients.claim()` means an old route chunk can miss the new `ASSET_SET` (`:107`), fall to network-first (`:118-127`), and receive Caddy's `try_files → /index.html` (`deploy/Caddyfile`) — HTTP 200 `text/html` cached under a `.js` path. The dynamic import then dies on MIME/parse. Separately `pwa.ts:34-38` reloads on `controllerchange` — which `clients.claim()` fires on **first** install, so a brand-new user's page reloads itself right after the 3.18 MB precache finishes — while `applyUpdate()` sets `updateApplied = true` (`:59`) _before_ posting `SKIP_WAITING`, so the reload its own comment promises never runs.
- **iOS eviction is unaddressed.** A non-installed PWA is evicted after ~7 days of disuse; no `beforeinstallprompt`/`standalone`/install string exists anywhere in `web/src`.

## 4. UX improvement plan

Five themes, each addressing a cluster of confirmed findings rather than a single symptom.

### 4.1 Make the app tell the truth about itself

The highest-value UX work is not new capability — it is removing false reassurance.

- Replace the combined `sync()` with per-direction replication (`db.replicate.to(remote, {live:true, retry:true})` and `.from(...)`) so `sync.ts` can listen for each direction's own `paused(err)`/`error`/`requestError` events, and only call `markSynced()` after a genuine `checkpoint`/`change`. Add a real request probe before declaring success.
- Derive `pendingChanges` from **unpushed local writes**, not `navigator.onLine`, and make `pending` a state that is actually reachable.
- Turn the amber pill's dead markup (`SyncStatusPill.svelte:26,80,88-90`) into the real "N changes not backed up" affordance.
- Fix the failure-as-emptiness inversions: a rejected read must render `ErrorState` with Retry, never "Plan your first trip" or "may have been deleted on another device".
- Remove `<WifiOff />` from the `{#if online}` branch; fix `toast.error(t('flight_removed'))`; fix the "permanently clear" copy to match soft-delete behaviour.

**Acceptance criteria.** With the remote URL pointed at a closed port: state is `offline` or `pending` (never `synced`), the pill shows amber, the banner is visible, and creating a trip increments the unsynced count. With the server restored: state reaches `synced` only after a `checkpoint` event, and the count clears. A forced IndexedDB rejection on `/` renders a retryable error state, not the empty state.

### 4.2 Never destroy what the user typed

- Add an `isDirty` guard to `Sheet.svelte`'s `requestClose()` — a "Discard changes?" confirm — and **remove the touch handlers from the `<header>`** (`Sheet.svelte:167-174`) so only the 40px drag handle dismisses. This is a two-line fix that removes the mobile failure mode even before the guard lands.
- Extend Undo to match the app's own model: checklist delete (`checklist/+page.svelte:188-196`) and template removal (`settings/+page.svelte:277-285`) currently have none, while itinerary already does. Pause the 8s Undo timer on hover and focus (`toast.ts:40`).
- Guard the Trash screen: group by parent trip, restore through the cascading `trips.restore` rather than `restoreDoc`, and add a retention policy with a countdown.

**Acceptance criteria.** A downward drag on a sheet header does not close it. Closing a modified sheet by any route (backdrop, Escape, X, drag) prompts before discarding. Every soft-delete offers Undo. Restoring a child of a deleted trip either restores the parent too or refuses with an explanation.

### 4.3 Make the artefact you carry match the screen

Detailed in §8. The UX decision that matters: **stop printing "the current tab"**. Printing is a document export, not a screenshot, and it should be a deliberate route with a visible scope.

### 4.4 Give the phone back its primary interactions

- Fix the map: `dragging: true`, 44px touch targets for `.leaflet-touch .leaflet-bar a`, and `z-[60]` (or `bottom-[calc(4.5rem+env(safe-area-inset-bottom,0px))]`) on the fullscreen wrapper.
- Fix reorder: `siblingIds()` should filter by the whole-day order, not by exact `startTime` equality — `move()` already proves the intent.
- Restore press feedback: add `active:` states to the eight row types that lack them, and keep the tap highlight on non-interactive surfaces.
- Replace fixed heights with viewport-relative ones (`h-80` → `h-[min(20rem,45dvh)]`; resolve the `min-h`/`max-h` conflict on the overview grid).

**Acceptance criteria.** On a 393×852 phone: the map pans by drag and zooms with 44px buttons; the fullscreen pin strip is fully visible and tappable; Move up/down are enabled for a day with three items at distinct times; every list row shows a visible pressed state.

### 4.5 Make language a first-class, verified property

- Type the dictionary: `export type TranslationKey = keyof typeof en;` and `t(key: TranslationKey, …)`. This converts all five missing keys into `svelte-check` errors — the project currently passes at 0 errors and would catch every one.
- Add a parity test asserting `Object.keys(en).sort()` deep-equals `Object.keys(ptBR).sort()` and that no value is empty.
- Set `document.documentElement.lang` in `setLanguage` and `initLanguage`, and mirror the theme pre-paint pattern (`app.html:20-27`) with an `itinera_lang` localStorage key so the first paint is in the right language.
- Sweep the 237 untranslated attributes and 86 toasts, **starting with the hardcoded Portuguese** (`itinerary/+page.svelte:333`, `TripMap.svelte:449`, `TripDataMenu.svelte:223`, `ItineraryItemSheet.svelte:473`) because those break the English build and have no key yet.

**Acceptance criteria.** A typo in any `t()` call fails `svelte-check`. Adding a key to `en.ts` without `pt-BR.ts` fails `vitest`. Loading with `itinera_lang=pt-BR` renders Portuguese on the first frame, and `<html lang>` reads `pt-BR`.

## 6. Mobile strategy

**Principle: the phone is the device at the destination, not a smaller desktop.** Design for one hand, no signal, low battery, and a queue.

1. **Touch targets.** 44px minimum already exists as `min-h-touch`/`min-w-touch`. The exceptions are Leaflet's 30px zoom buttons and the day chips. Add a touch override in `app.css`: `.leaflet-touch .leaflet-bar a { width:44px; height:44px; line-height:44px }`. Fix the `z-50` collision so the fullscreen map isn't under the tab bar.
2. **Viewport honesty.** Replace every fixed height with a viewport-relative one. The map is `h-80` → `h-[min(20rem,45dvh)]`; resolve `WholeTripOverview.svelte:270`, where `min-h-[450px]` beats `max-h-[calc(100vh-200px)]`. Use `dvh`, not `vh` — the codebase already does elsewhere.
3. **Safe areas** are already wired (`pb-safe`/`pt-safe`, `viewport-fit=cover`). Note the ordering bug: `app.css:161-162` emits `.pb-safe`/`.pt-safe` _after_ Tailwind's padding utilities, so they **replace** `py-4`/`py-2` rather than composing. Move them into `@layer utilities` so Tailwind's cascade order applies.
4. **Gestures** need a vocabulary and an escape hatch: swipe-to-complete on checklist rows, swipe-between-days on the itinerary, and Undo for anything a gesture changed. But first, remove the touch handlers from `Sheet.svelte`'s `<header>` — a gesture that silently destroys work is worse than no gesture.
5. **Feedback.** Restore press states on the eight row types that lack them (`MenuItem:22`, `ExpenseRow:41`, `ChecklistGroup:139`, `DateStrip:100-105,122-127`, `+page.svelte:253-269`, `checklist/+page.svelte:246-254`, `TimelineEntryRow:158-163`).
6. **Low-end compositing.** Cut to at most one always-on blurred layer: the sticky header keeps `backdrop-blur`, the bottom bar and pin strip go opaque. Extend the orb mitigation at `app.css:271-276` above 640px, or gate it on `@media (prefers-reduced-motion)` and `deviceMemory`.
7. **Manifest.** Unpin `"orientation": "portrait"` (it hides landscape defects on Android while iOS still shows them) and fix `"background_color"` to match `#fbf7f1`/`#111613`.
8. **Install prompt.** No install string exists anywhere in `web/src`. Add an iOS install nudge — a non-installed PWA is evicted after ~7 days, which is the mechanism by which the false "Synced" becomes permanent loss.

## 7. Widescreen strategy

def aggregate(expenses, home_ccy, traveler_count):

### 14.3 The interaction vocabulary

The three gesture surfaces share one pure geometry module, `web/src/lib/gestures.ts`. Shared rules and per-surface limits:

- **Drag** starts only from `[data-drag-handle]`, after a 6 px threshold; once the pointer is clearly vertical the drag is cancelled so native scrolling wins. Cross-day drops hit `[data-drop-date]` chips; same-lane insertion uses `dropInsertionIndex` / `insertionToIndex`. The lane shows optimistic order and restores the previous order if `setOrder` rejects. A completed drag swallows exactly one click; Escape and pointercancel leave the list untouched.
- **Checklist swipe** activates after 14 px of horizontal intent, completes at 56 px and clamps at 96 px. A no-op direction is damped to a quarter of the travel, so the row says "nothing to do" before release. Completion is sent only when it changes the item, and the toast's Undo toggles it back. The checkbox keeps its full accessible label; the gesture is an addition, never the only control.
- **Day swipe** completes at 64 px and clamps at 80 px; left advances, right goes back, and the boundary damps rather than blocks. Pointers starting on a drag handle, link, button, form control, editable element or `.leaflet-container` are ignored, and a completed swipe swallows the click it would otherwise produce.
- **Batch** writes run through `Promise.allSettled`, so one failed item cannot hide the others; a partial result warns with succeeded/failed counts instead of claiming success. Delete is a move to Trash and its Undo calls `trash.restoreMany` with the ids captured before the rows left the day.
